# r2：R2 区域代理的接口需求与缺陷（M2）

> 唯一写入者：R2 区域代理（只**追加**；ARCH §2.12、§15.4、§15.6）。引擎维护者的处理结论写在 `docs/requests/m2-engine.md`，不写在这里。
> 覆盖区域：`r2`（三号楼一单元）与 `r2_502`（王奶奶家）。

## 1. 区域没有办法打开“墙上的文档”（非随身文档）给玩家读
- 类型：接口需求
- 现象/需要什么：GDD §13.9 规定 `doc.donation_board`（加装电梯捐款榜）的位置是交互物 `r2.donation_board`，同理 R1 的 `doc.obituary`/`doc.demolition`/`doc.water_notice`（`r1.notice_board`）、`doc.estate_sign`、`doc.shrine_couplet`、`doc.cctv_notice`，R3 的 `doc.darkroom_rules`，R4 的 `doc.market_rules`/`doc.old_book`。这些文档不属于任何物品，`readDoc()` 只能读随身文档；区域能拿到的 `GameApi` 里没有 `journal.openDoc`，也没有对应的 Effect，所以交互物按 E 时打不开阅读器（ARCH §6.16 的阅读器、褪字层、取景器扫描线都用不上）。建议：`GameApi` 增加 `openDoc(id: DocId, o?: { vf?: boolean }): void`（= `JournalSystem.openDoc`，推 `mode.journal`，按 settle 语义在阅读器打开时 settle），或 Effect `{ do:'doc', id }` / `E.doc(id)`；dialogue/交互物的 Handler 里写 `E.doc(DOC.DONATION_BOARD)`。
- 影响：GDD §7.4 `doc.donation_board` 的呈现方式（不阻塞 §11 任何步骤；步骤 13–26 不读捐款榜）。
- 备注：与 `r1-world.md` #1、`r4.md` #1 是同一个需求，一次解决即可。
- 临时绕开：`r2.donation_board` 按 E 开一段旁白对话 `dlg.r2.donation_board`，逐行念出 GDD §7.4 的全文（`src/areas/r2/text.ts` 的 `DONATION_LINES`）；捐款榜贴图上本身也印着这两行（取景器里能读）。resolved 后换成 `E.doc(DOC.DONATION_BOARD)`。
- 状态：resolved（M3）：`GameApi.openDoc(id, o?)`/`openJournal()` 与 Effect `E.doc(id, vf?)`/`E.journal()`（`game/effects.ts`；阻塞到阅读器合上，连写几个就是一张接一张读；阅读器开着时 settle 为 'waiting'），`DebugState.doc`（`debug/api.ts`），测试助手 `readDocs`（`scripts/lib/harness.mjs`）；ARCH §6.3、§6.16、§12.3。R2 已换回阅读器：`r2.donation_board` 的 `onInteract: [E.doc(DOC.DONATION_BOARD)]`（`r2/logic.ts`），`dlg.r2.donation_board` 与 `DONATION_LINES` 删除。

## 2. 截图机位不能设区域临时状态：拍不到“声控灯亮着”的楼道
- 类型：接口需求
- 现象/需要什么：R2 的声控灯只由快门点亮 20 秒（GDD §3.3 M2、P3），亮灭是区域临时状态 `temp(lamp_lit_<n>)`（ARCH §0.3、§11.2），不是 flag；`ShotDef.preset` 只能给 flags/物品/照片，`__game.shot()` 也不按快门，所以任何截图机位里楼道的灯都是灭的（只有 0.12 的环境光保底）。“声控灯亮起的那一下”是本区的主画面，评审看不到。建议：`ShotDef` 增加 `temp?: Record<string, boolean | number>`（`runShot` 进区域、摆好机位之后对当前区域 `ctx.setTemp` 逐项写入，再等 settle 帧），或 `setup?: (ctx: AreaContext) => void` 钩子。
- 影响：ARCH §12.5 截图评审（`shots.mjs --area r2` 的画面代表性），不影响 §11 步骤。
- 临时绕开：灯灭时靠窗外的钠灯（走廊南窗、楼梯间窗、单元门外，都是 HDR emissive）与 0.12 的环境光过亮度验收；回放 `seg.lobby_2008` 里门厅灯是亮的（2008 年灯还是好的），`shot.r2.replay_2008` 用它看灯亮着的门厅。resolved 后给几张机位加 `temp: { lamp_lit_1: true }` 等。
- 状态：resolved（M3）：`ShotDef.temp`（`debug/shots.ts`：进区域后、摆机位前 `ctx.setTemp` 逐项写入，再推进淡入的 0.6 秒）；R2 的 update 在 `lamp_lit_<n>` 被别处写成亮时当作刚点亮过（`r2/logic.ts`），新增机位 `shot.r2.lobby_lit`、`shot.r2.f3_lit`（`r2/shots.ts`）。ARCH §12.5。

## 3. 自由机位截图（`view.cam`）只隐藏了主角的身子，摄像头脑袋还悬在出生点
- 类型：引擎缺陷（WP7 `debug/shots.ts` 的 `runShot` / WP2 `PlayerModel.setVisible`）
- 现象/需要什么：ARCH §12.5 写 `view: { cam }` 是“自由机位（隐藏玩家）”，`runShot` 调 `game.playerModel.setVisible(false)`，但 `setVisible` 只隐藏身子（尾声“身体不见”的语义），头（`head.group`，self_head 层，固定机位也渲染它）与视频线还留在出生点上方 1.8m。复现：`shot('r2_502', 'shot.r2_502.entry')` 的旧版机位（相机在出生点 (1.2,0,-1.2) 附近朝东看）画面正中是一颗悬空的摄像头。建议 `runShot` 的 cam 分支另外把 `playerModel.root.visible = false`（下一张机位或 `reset()` 复原），或给 `PlayerModel` 一个“整体隐藏”的开关。
- 影响：截图评审；不影响玩法与 §11 步骤。
- 临时绕开：R2/R2_502 的自由机位都避开出生点附近（或改用 `player` 机位）。
- 状态：resolved（M3）：同 r1-world.md #4——`runShot` 的自由机位连 `playerModel.root` 一起藏（`debug/shots.ts`），ARCH §12.5。

## 4. `scripts/shots.mjs` 的截图用 Playwright 默认 30 秒超时，M2 并行负载下 r2 第一张就中断
- 类型：引擎缺陷（WP7 `scripts/shots.mjs` 第 66 行 `h.page.screenshot({ path: file })`）
- 现象/需要什么：M2 五个区域代理同时跑 SwiftShader（load average 15–40），`CAMERA_DIST=<r2 构建> node scripts/shots.mjs --area=r2,r2_502` 在 `shot.r2.lobby_door` 就抛 `TimeoutError: page.screenshot: Timeout 30000ms exceeded`，`main()` 直接退出，后面的机位全没拍、也不写 perf.json（与画面无关）。建议给截图传 `timeout: 180_000`（`launch` 的 callTimeout 同理可放宽或读环境变量）。与 `r3.md` #6、`r4.md` #3 是同一个需求，一次解决即可。
- 影响：ARCH §15.4 完成定义“`shots.mjs --area <id>` 产出 ≥ 8 张截图并通过验收”（不涉及 GDD §11 步骤，regions 脚本无 blockedBy）。
- 临时绕开：私有拷贝（`scratchpad/r2w/shots.mjs`：同样的亮度/关键对象/预算验收，截图超时 300 秒）跑 r2 的 10 张与 r2_502 的 8 张，全部通过；负载低时再用正式脚本复验。
- 状态：resolved（M3）：`scripts/shots.mjs` 截图超时 `CAMERA_SHOT_TIMEOUT`（默认 180 秒）、调用超时 `CAMERA_CALL_TIMEOUT`（默认 400 秒），单张出错（含截图超时）只记为该机位的问题、不中断整轮；带 `--area` 时 perf 写 `perf.<区域,…>.json`。ARCH §12.5。

## Lessons
- `src/areas/r2/` 与 `src/areas/r2_502/` 在 `check.mjs` 眼里是两个区域（`areaOf` 取目录名），互相 import 算 cross-area-import：同一个代理写的两个目录也只能各留一份小工具（`build/batch.ts`），文本分放两个 `text.ts`；对话 id 前缀按目录分别是 `dlg.r2.*` 与 `dlg.r2_502.*`，过场 `cs.r2_502.*`。
- 声控灯这类“只靠快门点亮 20 秒”的临时状态，`__game.shot()` 摆不出来（`ShotDef` 只能设 flags/物品/照片）；灯灭时的截图要靠 HDR 的窗外夜景（`MeshBasicMaterial` 颜色 ×2.5–3.4）过“亮度 > 0.8 的像素 ≥ 0.5%”，回放里的“过去”（2008 年灯是好的、2018 年上午的天光）可以改灯的颜色/强度/位置（灯数不变）拍灯亮着的样子。
- 半球光的地面色近黑（R2 `#0E0C0A`）时，灯灭的顶棚是一整块死黑、顶棚上的灯座“看不清”（关键对象 5×5 亮度 ≤ 0.04）：给顶棚材质一点点 emissive（0.2 左右的暗暖色）当“窗外反光”，灯座塑料件 emissive 0.1。
- 交互拾取：锚点必须落在 `hit` 网格里面（空灯座的锚点比灯头低 3cm，准星就射到顶棚上、被当成“挡住”，只能靠就近聚焦碰运气）；楼梯口这种被栏杆、扶手挡着的交互物给一块 `MATERIALS.hitProxy()` 挡板当 hit（每层一块、只显当前层）；就近聚焦先比 priority 再比距离，给一个交互物加 priority 会把附近别的东西的就近聚焦抢走。
- 第三人称相机的球形避障只认碰撞体：没给顶棚加碰撞体时，楼道里第三人称相机会钻到顶棚平面上面去（单面顶棚从上面看不见，画面里多出一截墙）。每层加一块顶棚碰撞板。
- `setFlags()`/`setState()` 不带 area 时走 `debugSet`，不发 `'flag'` 事件：动态碰撞体（502 门）、区域 `onFlag` 都不会重算——测试里改完 flag 要带 `area` 重进区域。
- `sit` 姿势的“座高”约 0.39m（人偶 1.5m）：让 NPC 坐在台阶上，台阶就得有 0.36m 左右高，或者把 NPC 摆在二级台阶上。
- 机器负载高（多个代理同时跑 SwiftShader）时 `scripts/shots.mjs` 的 `page.screenshot` 30 秒默认超时会失败：迭代时用私有脚本（同样的验收标准、截图超时放宽到 180s），最后再跑正式的 shots.mjs。
- 回放片段的函数形式道具由 `ReplaySystem.prebuild` 建、`clearArea` 摘掉但不释放：几何与区域自建材质要 `ctx.track()`（R2 的 `tracked()`），否则每进一次区域泄一批几何。
- （M2 第二段）灯灭着的楼道（环境光 0.12）里，墙上的贴花（小广告、喷的电话、红章）几乎看不见：要让它们“凑近认得出”，贴花材质给 `emissiveMap = map`、`emissiveIntensity` 0.1 左右（同招牌的 0.16），不要去提环境光。
- 截图机位的高光（亮度 > 0.8 的像素 ≥ 0.5%）在 R2 只能靠 HDR 的门外/窗外夜景（`MeshBasicMaterial` 颜色 ×3–4.4，钠灯光团的白芯要占光团半径的 ~20%）和取景器里残影点的雪花（白点算高光）；窗子在画面里要尽量正对（掠射角 > 70° 时只剩一条缝）。回放机位的玩家位置必须在残影点 2.5m 以内（`runShot` 从 `view.player` 直接按 R），所以回放画面的高光要在残影点附近找（R2 在五楼 502 门边加了一扇西头小窗，2018 年上午的天光从这里进来）。
- `__game` 不暴露场景对象；无头测试里要查网格（贴花在不在、UV、包围盒），可以在 `page.addInitScript` 里装一个 `window.__THREE_DEVTOOLS__ = new EventTarget()` 收集 three 的 `observe` 事件（`Scene` 构造时派发），再 `h.goto(query)` 重新加载——纯调试用，不进仓库。
- （M2 第三段）编排脚本给的 scratchpad 目录是**所有并行代理共用**的：自己的脚本、日志、截图一律放进带区域前缀的子目录（R2 用 `scratchpad/r2w/`），不要用 `myshots.mjs`、`shots/`、`shots-run1.log` 这类通用名——本段第一个私用截图脚本就被别的代理同名覆盖了。
- 等后台任务别用 `until ! pgrep -f "<命令片段>"`：等待的那条 bash 命令行本身就含这个片段，`pgrep -f` 永远匹配到自己（死等）；`pkill -f` 同理会把自己的会话也杀掉（exit 144）。要串行就在同一条后台命令里用 `;` 顺序执行。
- 负载高时完整的 `regions/r2.mjs` 要 50 分钟上下（27 个用例，每例都 newGame + setState 重建，60–150 秒一例）：`timeout` 给到 2 小时，或者按 `--only=cases --case=<子串>` 分批跑。
- 要看清的叠层（灶君的眼珠）别做成 HDR：眼白 ×2.2 时 Bloom 晕开，眼珠整个被糊成灰色，“往左下瞟”看不出来。眼白压在 ×0.8–0.9（刚过 Bloom 阈值、仍算高光像素），会动的深色部分（眼珠）放大一圈、用不受光的 `MeshBasicMaterial`，Bloom 的外溢盖不住它。线索贴图按 ×2 画（768×1024），3× 取景器里不糊。
- 加法混合的“月光落在地上”贴花：遮罩必须在四边形内部就淡到 0（先 `filter = 'blur()'` 再画、四周留边），否则看起来是一块浅色地毯；窗格影子用 `destination-out` 画窗棂。
- 暗屋里“家具搬走留下的灰印”只有在灰层自己带一点自发光（`emissiveMap = map`、淡灰 0.4）时才看得出：满地一层匀匀的灰，干净的地方是更暗的红漆地；只靠受光在 0.12 的环境光里整片是黑的。
- 平涂的 `MATERIALS.dado` 墙显得新：每面墙在同一个 Batch 里叠一层 512² 的透明“做旧”贴图（顶棚下熏黑、墙裙线上方蹭脏的一道、掉漆碎点、踢脚鞋印，横向平铺、每段 u 起点错开），每层只多一个 draw call。
- 吸顶的声控灯：点光放在灯泡下方 0.55m（不是 0.35m），顶棚上只剩一圈昏黄的光晕，不再整块烧白；墙裙与地面的受光几乎不变。
