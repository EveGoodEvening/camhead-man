# R4（人民路地下通道·鬼市）的需求与缺陷

> 唯一写入者：R4 区域代理（M2）。格式见 ARCH §15.6；处理结论由引擎维护者写在 `docs/requests/m2-engine.md`。

## 1. GameApi 没有打开文档阅读器的入口：世界里的文档（规矩牌、旧书残页）读不了
- 类型：接口需求
- 现象/需要什么：GDD §13.9 规定 `doc.market_rules` 在 `r4.rules_board`（与门童灯笼）上、`doc.old_book` 在 `r4.old_book` 上，二者都不属于任何物品。
  区域的 `onInteract` 只拿得到 `GameApi`，它没有 `journal.openDoc` 一类的方法，也没有对应的 Effect，所以对规矩牌、旧书按 E 时打不开 §6.16 的文档阅读器
  （R1 的 `r1.notice_board`/`r1.estate_sign`/`r1.cctv_notice`/`r1.shrine`、R2 的 `r2.donation_board`/`r2.zaojun`、R3 的 `r3.darkroom_rules` 应是同一个问题）。
  需要其一：`GameApi.openDoc(id: DocId): ApiResult`（= `JournalSystem.openDoc(id, { vf: modes.has('mode.viewfinder') })`，压 `mode.journal`、settle 为 waiting），
  或 Effect `{ do: 'doc'; id: DocId }` / `E.doc(id)`。
- 影响：GDD §11 步骤无（38–45 不读这两份文档）；regions 脚本里没有 blockedBy。
- 临时绕开：`r4.rules_board`、`r4.old_book` 的 `onInteract` 开一段旁白对话（`dlg.r4.rules_board`、`dlg.r4.old_book`），逐字读出 GDD §7.4 的原文；
  两份文档照常在 `AreaDef.docs` 里登记。接口有了以后只改 `src/areas/r4/logic.ts` 里这两条 `onInteract`。
- 状态：resolved（M3）：`GameApi.openDoc(id, o?)`/`openJournal()` 与 Effect `E.doc(id, vf?)`/`E.journal()`（`game/effects.ts`；阻塞到阅读器合上，连写几个就是一张接一张读；阅读器开着时 settle 为 'waiting'），`DebugState.doc`（`debug/api.ts`），测试助手 `readDocs`（`scripts/lib/harness.mjs`）；ARCH §6.3、§6.16、§12.3。R4 已换回阅读器：`r4.rules_board`、`r4.old_book` 分别 `E.doc(DOC.MARKET_RULES)`、`E.doc(DOC.OLD_BOOK)`（`r4/logic.ts`），`dlg.r4.rules_board`/`dlg.r4.old_book` 删除；`regions/r4.mjs` 用 `readDocs` 断言。顺带修了两处 M3 才暴露的问题：大厅顶板没有碰撞体，低头看摊桌时第三人称相机被吊臂顶到 3.3m、钻到顶板上面（`r4/build/corridor.ts` 加顶板碰撞体）；`r4.old_book` 的锚点降到书面上方 5cm（`interact` 的转向改成迭代到收敛后正好瞄准锚点，锚点在代理中部时射线会越过书面先扫到黄三爷）。

## 2. ReplaySystem.clearArea 不释放“函数形式”的片段道具
- 类型：引擎缺陷（轻微）
- 现象/需要什么：`game/replay.ts` 的 `buildSeg` 对 `props[].mesh` 为函数的道具 `dispose = null`，`clearArea()` 只 `removeFromParent` 片段根节点，
  道具的 geometry/material 既不被 `ReplaySystem` 释放，也不在区域 Disposer 的追踪里（片段根节点在 Disposer 遍历 root 之前就被摘下了）。
  区域每次进出都新建一份道具的话，资源计数会涨（ARCH §13.3“区域切换 5 次后 geometries/textures 回到基线 ±5”）。
  建议：函数道具建好后 `dispose = () => obj.traverse(释放非共享 geometry/material/texture)`，或在 ARCH §6.9 写明“函数道具的资源由区域负责缓存/释放”。
- 影响：GDD §11 步骤无；regions 脚本里没有 blockedBy。
- 临时绕开：R4 的片段道具（录像带箱、那盘带子、红绸、横幅、1997 年的摊桌、黄鼠狼眼睛的反光）的 geometry/material/贴图在 `src/areas/r4/replay.ts` 里按模块缓存一次、
  反复进出区域复用，不新建。
- 状态：resolved（M3）：`game/replay.ts` 的函数道具在 `clearArea()` 时用 `Disposer.trackObject` 释放几何、非共享材质与贴图；ARCH §6.9 写明。R4 在模块里缓存复用道具资源的做法保留（释放后再用会重新上传，不泄漏）。`scripts/roundtrip.mjs` 实测 r1 ↔ r2/r2_502/r3/r4 各往返 5 次 geometries/textures 回到基线。

## 3. scripts/shots.mjs 的截图用 Playwright 默认 30 秒超时，M2 并行负载下整轮中断
- 类型：引擎缺陷
- 现象/需要什么：M2 期间 5 个区域代理同时跑 SwiftShader（机器 load average 60+），`h.page.screenshot({ path })` 偶尔超过 Playwright 默认的 30 秒，
  抛 `TimeoutError: page.screenshot: Timeout 30000ms exceeded`，`main()` 的 catch 直接退出，后面的机位全没拍、也不写 perf.json。
  复现：负载高时 `CAMERA_DIST=<dist> node scripts/shots.mjs --area r4`（R4 第一轮在第 2 张就断了）。
  建议：`page.screenshot({ path: file, timeout: 180_000 })`，`launch` 的 callTimeout 也放宽（或读环境变量）；另外 `shots.mjs` 把 perf.json 写进共享的
  `test-artifacts/shots/`，几个区域并行跑时互相覆盖，可按 `--area` 拼文件名（`perf.<area>.json`）。
- 影响：GDD §11 步骤无；完成定义里的“shots.mjs 产出 ≥ 8 张截图”在高负载时跑不完。regions 脚本无 blockedBy。
- 临时绕开：R4 在自己的 scratchpad 里复制了一份 shots.mjs，只把截图超时改成 300 秒、callTimeout 改成 400 秒、输出目录改到私有目录，判定逻辑不变；负载低时再用原脚本复验。
  （第二轮 M2 会话再验：load 57 时原脚本仍在第 1 张截图处超时退出；私有副本 13/13 通过。）
- 状态：resolved（M3）：同 r2.md #4（截图/调用超时可配、单张出错不中断、`perf.<区域>.json`）。

## 4. 自由机位（ShotDef.view.cam）只隐藏玩家身子，摄像头脑袋与视频线照样渲染
- 类型：引擎缺陷（轻微，只影响截图）
- 现象/需要什么：`debug/shots.ts` 的 `runShot` 对 `cam` 机位调用 `game.playerModel.setVisible(false)`，而 `rigs/player.ts` 的 `setVisible` 只切身子网格与脚下假阴影
  （头可拆下装上支架，所以不归 `setVisible` 管）。玩家站在出生点，自由机位只要把出生点框进画面，半空里就飘着一颗摄像头脑袋和垂下来的视频线。
  复现：R4 `shot.r4.boy_chou` 早先的机位 `{ cam: { pos: [-18.3,1.5,1.7], target: [-15.4,1.2,-1.7] } }`（出生点 (-17,0,0.5) 在机位与门童之间）。
  ARCH §12.5 写的是“自由机位（隐藏玩家）”。建议 `cam` 机位同时隐藏 `playerModel.head`（或整棵 `playerModel.root`），截完复原。
- 影响：GDD §11 步骤无；regions 脚本无 blockedBy。
- 临时绕开：R4 的自由机位都避开出生点（`src/areas/r4/shots.ts` 文件头有注释）。
- 状态：resolved（M3）：同 r1-world.md #4（自由机位连 `playerModel.root` 一起藏）。

## 5. 黄鼠狼头的胡须（LineSegments）不被人偶 dispose() 释放，回放里的黄鼠狼每进一次区域漏一份
- 类型：引擎缺陷（轻微）
- 现象/需要什么：`rigs/humanoid.ts` 黄鼠狼头（约 976 行）给胡须建 `new THREE.LineSegments(new BufferGeometry(), new LineBasicMaterial())`，
  而人偶的 `dispose()` 只释放 `isMesh` 的几何（约 906–908 行），胡须的几何与材质从不释放。
  R4 两段回放各有一个黄鼠狼人影（`ghost.huang_2023` 是 `character: 'huang'`，`ghost.weasel_eyes_1997` 是 `variant: 'weasel'`），
  ReplaySystem 每次进区域都新建人影，于是每进出一次 R4 漏 2 份几何。
  复现：`r1 ↔ r4` 往返 5 次，`perf().geometries` +55（其中 R4 的 10 份就是胡须；另外 45 份在 `r1 ↔ r3` 往返里同样出现，不是 R4 的）。
  定位办法：在构建副本里挂出 Game，钩住 `EventDispatcher.prototype.addEventListener/removeEventListener('dispose')` 统计仍在 GPU 上的几何，
  再对照进 R4 时场景里每个几何的主人路径（`Scene/area:r4/replay:seg.stall_2023/ghost.huang_2023/huangWeasel/…/headSlot/whiskers`）。
  建议：人偶 `dispose()` 改成遍历时释放 `Mesh | Line | Points` 的非共享几何与材质。
- 影响：GDD §11 步骤无；ARCH §13.3“区域切换 5 次后 geometries 回到基线 ±5”；regions 脚本无 blockedBy。
- 临时绕开：`src/areas/r4/logic.ts` 的 `r4OnExit` 在卸载前遍历 `ctx.root`，自己释放名为 `whiskers` 的 LineSegments 的几何与材质（每次新建、不共享，释放安全）。
  绕开后 R4 每趟往返不再多出几何；`r1 ↔ r4` 与 `r1 ↔ r3` 往返仍各每趟涨 9 份，同法查出全在 R1：`seg.tree_1984` 的函数道具 `camera1984`（5 份）与
  `seg.shed_2012` 的 `bike2012`（4 份）——就是本文件 #2（ReplaySystem 不释放函数形式的片段道具），不在 R4，供引擎维护者一并处理。
- 状态：resolved（M3）：`rigs/humanoid.ts` 的 `dispose()` 遍历 `Mesh | Line | Points`，线/点的非共享材质一并释放（ARCH §5.1）；R4 `r4OnExit` 里自己释放胡须的绕开已删除。

## Lessons
- 伪装成纸人的黄三爷与九个实例化摊主要“动作也一样”：`createPaperStalls` 的实例矩阵与 `CharacterRig.props.masked`（纸人根节点）用同一个晃动公式
  （`build/market.ts` 的 `paperSway`），每帧更新；揭面具后才停。灯笼、角标、`offers`、拾取距离都按组一致写。
- 纸灯笼贴图带字时用 `MeshBasicMaterial`（自己亮、不受旁边真实点光照射），否则灯芯那盏点光把纸面照成一团白；亮度 ≈ 灯笼白 × 1.0–1.1 就能出 Bloom 又透出字。
  灯笼离纸脸 0.6–0.75m、点光在灯笼靠过道一侧时，4× 近看纸脸不过曝，又能提供 ≥0.5% 的高光（`shots.mjs` 要求）。
- 4× 的取景器机位画框只有约 0.5m 高：要让画面里有灯芯，只能靠被照亮的主体本身或紧挨着它的灯；先算视场再摆灯。
- 低矮的摊桌用动态碰撞体时加 `{ seeThrough: true }`：否则 `interact()` 的视线检查（碰撞体射线）会被桌子挡住桌上与桌后的交互物（旧书、樟木箱）。
- 开市前后灯数恒定：灯管 3 盏点光在开市后置 0、灯笼 3 盏在开市前置 0；开市动画里只改强度，不增删灯；`scene.fog` 在区域里直接改 `FogExp2` 的颜色与密度（`ctx.fog()` 每次新建对象）。
- 水平的加法混合“地雾”平面不要抬高：y=0.55 的一层从 1.8m 视点往下看，会把它下面的地面、桌脚整片刷成一汪青水（第一轮截图就是这样）；
  贴地雾只放在 y≈0.05，遮罩画成稀疏的几团，远处的“雾”交给 FogExp2。
- 第三人称俯仰只到 -35°：桌面上的旧书、墙根的矮箱子，站在过道里按 E 时准星够不着，最近者规则又会落到旁边优先级更高的 NPC 上。
  做法：给矮物体挂一块不渲染的 `MATERIALS.hitProxy()` 子网格（挂在被 `ctx.ref` 的那个对象下面，拍照主体 ref 不变），锚点抬到代理中部；
  桌上的小物件放在靠过道的前沿，穿过它的准星射线先落在桌面（不透明、终止聚焦搜索），不会越过桌子碰到后面的黄三爷。
- 回放“隐去现世”可以整组做：`ctx.ref('r4_market', market.group)`（区域内部名，不带点，不算游戏 id）+ 片段 `hideWorld`，1997 年的剪彩就是一条空的新通道；
  回放期间的灯光在 `AreaDef.update` 里按 `ctx.game.replay.active?.seg` 切（灯管全亮、灯笼光置 0），退出回放那一帧按 flags 复原一次（只改强度，灯数不变）。
- M2 期间所有代理共用同一个 scratchpad 目录：别人会清空/覆盖 `scratchpad/shots` 这类通用名字的目录，私有的中间文件一律放进带区域前缀的子目录（R4 用 `scratchpad/r4-work/`）。
- 截图与区域测试在 load 60+ 的机器上一轮要 15–40 分钟：先用 `--only=cases --case=<子串>` 跑改动涉及的用例，最后再整轮跑；测试与截图各用一份构建目录（`r4-dist`、`r4-shots`），
  改代码后只重建当时没有脚本在用的那一份。
- 灯管的真实光别用点光挂在灯管上：点光离顶板 0.18m，顶板被照成一大团白（Bloom 再放大）。改用 `designLight('spot', …)` 朝下、半角 72°、penumbra 0.55
  （3m 外的墙照到 2m 高，顶板照不到），顶板上那点光用加法的径向贴花假（实例色跟着灯管亮度）；灯管本身 HDR ×3.5（×5 时近处两根连成一团）。
- 自由机位（`view.cam`）只藏玩家身子、不藏摄像头脑袋（#4）：机位一律避开出生点；回放机位（`view.replay`）的站位必须在残影点 2.5m 内（否则 `not_near_replay_point`）。
- 暗场景里“飘着的影子”用纯黑半透明 billboard 看不见（背景本来就黑）：给它配一道平躺在地上、从灯笼那排往过道拉长的地影（过道被灯笼照亮处才显），
  外加一圈极淡的加法青光（比身子大一圈，放在身子后面），暗处也看得出有东西在飘，又不吓人。
- 按时间直接算位置的飘落物（纸钱）要避开过道正中：截图机位、第三人称相机都在过道里，贴着镜头的一张 8cm 纸钱能占掉画面一角；落在摊桌上空、S3 摊子上空不落。
- 查“区域切换后 geometries 涨了”：跨区域 `goto` 只能沿出入口图走（r4 只通 r1，去不了 dev），用 `r1 ↔ X` 往返对比各区；要定位到对象，就在 scratchpad 里复制一份仓库、
  在 `mountDebugApi` 里把 Game 挂到 `window.__G` 再构建，页面里钩住 `EventDispatcher.prototype.add/removeEventListener('dispose')` 数还在 GPU 上的几何，
  对照进区域时场景里每个几何的主人路径——R4 这样查出来的是引擎人偶胡须的泄漏（#5），不改共享源码。
